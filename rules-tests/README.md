# اختبارات Firestore المحلية وصغط الطلبات

الاختبارات دي بتشتغل على **Firestore Emulator فقط**، ومش بتتصل بمشروع `wasally-12259` أو بأي قاعدة بيانات سحابية.

## المتطلبات
- Node.js 22 (أو 20+)
- Java 21 لتشغيل Firestore Emulator

## التشغيل
من داخل المجلد:

```bash
cd rules-tests
npm install
npm test
```

الاختبار يشغّل Firestore Emulator باستخدام `demo-wasally` على المنفذ 8080، ويقرأ قواعد المشروع من `../firestore.rules`.

## مراحل الحمل
الافتراضي: 2، 10، 25، 50، 100، 250، ثم 500 عميل متزامن. كل عميل ينشئ طلبًا جديدًا وبيانات التواصل في Batch واحدة. تظهر لكل مرحلة:
- عدد العملاء المتزامنين والطلبات الناجحة/الفاشلة.
- الزمن الكلي للمرحلة.
- P50 وP95 لزمن كتابة الـ Batch.

لتقليل الحمل المحلي أو رفعه حتى 1000 عميل:

```bash
WASALLY_STRESS_MAX_CLIENTS=100 npm test
WASALLY_STRESS_MAX_CLIENTS=1000 npm test
```

## حدود مهمة
- النتائج تقيس صحة قواعد Firestore وسلوك التزامن على المحاكي المحلي فقط؛ **لا تمثل قدرة Firebase السحابية أو Spark**.
- لا يوجد أي اختبار على بيانات العملاء الحقيقية، ولا أي نشر للقواعد أو الفهارس.
- الاختبارات تستخدم معرّفات منفصلة لكل محاولة، وتتحقق من رفض إنشاء مستند الطلب نفسه مرتين وفق قواعد Firestore الحالية.
- Cloud Functions ليست جزءًا من هذا الاختبار؛ الاختبار يركز على إنشاء الطلب وكتابة بيانات التواصل وفق القواعد الحالية.
